Data Modeling & Design

Data Model → The blueprint of how data is structured (tables, relationships, storage). Ensures data is clean, connected, and ready for analysis in tools/platforms like AWS Redshift, Azure Synapse, or GCP BigQuery.

ER Diagram (Entity-Relationship) → A visual representation of the schema, showing tables and their relationships.

Data Architect → The planner who decides where to store data, which models to use, and which platforms to adopt for a company’s data strategy.

Schemas & Tables

Star Schema → A simple model with one central Fact Table (numbers/metrics) surrounded by Dimension Tables (descriptive info). Great for easy reporting.

Snowflake Schema → An advanced version of Star Schema where dimension tables are further normalized into sub-tables, giving more detail but adding complexity.

Facts → Tables storing numbers, metrics, or measurements you want to analyze (e.g., sales amount, revenue).

Dimensions → Tables storing descriptive attributes to filter, group, or explain facts (e.g., customer name, region, product).

Data Management

Data Catalog → Stores metadata (info about datasets like names, data types, locations), not the actual data. Helps in searching and managing datasets.

Data Crawler → A tool that scans data sources (e.g., S3, databases), infers structure (columns, types), and updates the Data Catalog automatically.

Data Governance → Rules, policies, and responsibilities ensuring data is accurate, secure, and properly managed.

Data Mining → The process of analyzing datasets to discover patterns and insights that support business decisions.

Query Engines & Processing

Hive → A data warehouse system that converts SQL-like queries into MapReduce/Tez/Spark jobs. Mainly for batch ETL on very large datasets. Reliable but slower and not ideal for interactive queries.

Presto (Trino) → A distributed SQL engine for fast, interactive analytics across multiple data sources (Hive, S3, RDBMS, etc.). Great for BI dashboards/ad-hoc queries, but not suited for heavy ETL or ML.

Spark → A general-purpose distributed computing framework supporting SQL, ETL, ML, graph processing, and streaming. Faster than Hadoop MapReduce (due to in-memory execution) and widely used for end-to-end data pipelines.

Programming & Functions

Wrapper → A layer that hides underlying complexity, making tools or functions easier to use (like a TV remote). Also used in code to extend or add functionality to existing functions.

Lambda Function (Serverless) → Small, event-driven functions that run only when triggered. Example: Uploading a file to S3 can trigger a Lambda that processes and stores cleaned data elsewhere.

Serialization - Serialization in data like packing information into a specific format so it can be stored or sent somewhere else. Format like Parquet, Arvo

Data Terminologies

1. Data Ingestion – Collecting and importing data from various sources into a storage system (e.g., databases, data lakes)

2. ETL (Extract, Transform, Load) – Extracting raw data, transforming it into a usable format, and loading it into a destination system

3. ELT (Extract, Load, Transform) – Unlike ETL, data is first loaded into a storage system (like a data lake) before transformation

4. Data Pipeline – A series of steps that automate data movement and transformation from one system to another

5. Batch Processing – Processing large volumes of data at scheduled intervals rather than in real-time

6. Stream Processing – Processing data in real-time as it arrives, often used for live analytics

7. Data Lake – A centralized repository that stores raw, structured, and unstructured data for later use

8. Data Warehouse – A structured repository optimized for querying and analytics, storing processed data

9. Data Mart – A subset of a data warehouse, focused on a specific business domain or department

10. OLTP (Online Transaction Processing) – A system designed for handling real-time transactional data, like banking systems

11. OLAP (Online Analytical Processing) – A system designed for complex queries and analytical workloads, often used in reporting

12. Indexing – A technique to improve database query performance by creating a structured way to access data quickly

13. Sharding – Splitting large datasets into smaller, manageable chunks across multiple servers to improve performance

14. Partitioning – Dividing a large dataset into smaller parts within a single database to improve query efficiency

15. Caching – Temporarily storing frequently accessed data in memory to boost system performance

16. Data Governance – Policies ensuring data quality, security, and compliance across an organization

17. Data Lineage – Tracking where data originates, how it moves, and how it is transformed

18. Schema Evolution – The ability to modify a database or data warehouse structure without affecting existing data

19. Big Data – Large and complex datasets requiring specialized tools (e.g., Hadoop, Spark) for processing

20. Data Mesh – A decentralized architecture treating data as a product, allowing domain-oriented data ownership

21. Data Lakehouse – A hybrid architecture combining the features of data lakes and data warehouses for better flexibility and performance

22. Metadata – Data about data, providing information such as structure, source, and usage details

23. Data Modeling – Designing a structured format for storing and managing data efficiently

24. Data Orchestration – Coordinating various data workflows, often using tools like Airflow

25. Lambda Architecture – A data processing architecture handling both real-time & batch data
